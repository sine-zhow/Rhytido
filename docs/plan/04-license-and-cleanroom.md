# 04 · 许可证决策与净室方法论

> 草案 v1.0 ｜ 2026-11-12
> **重要声明**：本文许可证事实已核实（见来源），但**法律兼容性结论为工程推断，非法律意见**；正式立项前建议法务审查。

---

## 1. 许可证决策（建议）

**Rhytido 自身代码采用 Apache-2.0**（可选 Rust 惯例 **MIT OR Apache-2.0 双许可**）。

**为何 Apache-2.0 是"风险最小"的宽松协议**：
- **显式专利授权**：贡献者授予使用者专利许可，并有**专利报复终止**条款——MIT/BSD 无此保护，Apache-2.0 显著降低专利诉讼风险。
- **宽松、无 copyleft**：不传染下游，最大化可复用性/可嵌入性（契合 C/C++/Python 绑定与商用）。
- **GPLv3 兼容**（单向），生态接受度高。
- 条款清晰（含 NOTICE、变更声明），法律确定性高。

> 若追求 Rust 生态最大兼容，可双许可 MIT/Apache-2.0（使用者任选）；若只选一个且以"风险最小"为先，**Apache-2.0**（专利保护）优于 MIT。

## 2. 参考代码许可证分析（已核实）

| 组件 | 许可证 | 来源 | 对 Rhytido 的影响 |
|---|---|---|---|
| **Sollya** | **CeCILL-C**（文件级弱 copyleft，LGPL 类似） | 本地 COPYING/version.h + 官网 | 仅约束**复制了其代码的文件**；净室不复制则不传染 |
| Sollya **生成代码** | CeCILL-C **+ 特殊例外**（4.1 起） | implement.c 法律声明 | 产出代码可任意许可，**但排除"利用骨架的代码生成器"**→ Rhytido 作为生成器重实现**不在例外内** |
| **Gappa** | **CeCILL v2.1 + GPL 双许可** | Gappa COPYING | 若复用 Gappa 自身代码→更强 copyleft；仅生成 .g 输入文件不构成复制 |
| pythonsollya | CeCILL v2.1 | 项目页 | 参考接口风格，不复制代码 |

**核心结论**：因 Rhytido **完全净室、不复制 Sollya 代码**，CeCILL-C 的 copyleft **不附着**于 Rhytido 自身代码 → 可自选 Apache-2.0。**不能**用"生成代码例外"为生成器本身的许可背书（例外明确排除生成器）。

## 3. 净室方法论（降低"衍生作品"风险）

**目标**：确保 Rhytido 是独立实现，而非 Sollya 的衍生作品（翻译/改编）。

**做法**：
1. **规格来源**：以 Sollya **公开文档、数学论文、行为测试**为实现依据；算法/数学方法本身不受版权保护。
2. **不复制表达**：不逐行翻译 C 代码，不复制其具体结构/注释/命名表达；以 Rust 惯用方式独立设计实现。
3. **溯源记录**：维护实现溯源（每个模块的规格来源：文档章节/论文/测试），证明独立实现路径。
4. **行为测试驱动**：以"输入→输出"行为契约（语料）验证，而非对照源码逐行核对。
5. **法务审查**：正式立项前请法务评估净室主张。

**⚠️ 必须正视的风险（R1）**：本会话已**深度精读 Sollya 源码**。严格净室理想上要求"规格编写者"与"实现者"分离（实现者只看规格、不看源码）。我们两者同一，**净室主张的可辩护性被削弱**。缓解：
- 实现阶段**刻意以公开规格/测试为准**，避免把读到的具体表达直接搬入代码；
- 架构上采用 Rust 惯用设计（interning/facade/分层），与 Sollya 的 C 表达天然不同；
- 留存溯源与独立设计记录；
- **法务审查**确认。
> 如实说：这不是"绝对安全"，而是"以方法+记录+审查把风险降到可接受"。是否构成衍生作品最终是法律判断。

## 4. 依赖许可策略

**原则**：优先宽松（MIT/Apache）依赖，使全栈许可纯净；若用 LGPL，动态链接 + facade 隔离合规。

| 依赖 | 许可证 | 策略 |
|---|---|---|
| dashu | MIT/Apache | 优先（纯 Rust、宽松） |
| feanor-math（LLL） | MIT | 优先 |
| inari | MIT | 仅 f64，不用于多精度区间（参考其 IEEE 1788 设计） |
| lalrpop | **Apache-2.0 OR MIT**（已核实 crates.io 0.23.2，MSRV 1.86） | 解析器首选，宽松 |
| chumsky | **MIT**（已核实 crates.io 0.13.0，MSRV 1.65） | 解析器备选，宽松 |
| pest | MIT OR Apache-2.0（研究 B4 已核实） | 解析器备选，宽松 |
| **rug / gmp-mpfr-sys** | **LGPL-3.0+** | 若用：**动态链接** GMP/MPFR，facade 隔离；履行 LGPL（允许替换/重链接） |
| malachite | LGPL-3.0-only | 备选，同 LGPL 策略 |
| fplll（若 FFI） | LGPL-2.1+ | 动态链接；注意 5.5.0 ABI 断裂 |
| MPFI | COPYING 为 GPL-3 文本（确切待核） | **不链接**（自研区间层），规避 |

**facade 的许可价值**：后端可切换 → 若需全宽松栈，切 dashu+feanor（无 LGPL）；若需字节级保真/成熟度，用 rug（动态 LGPL）。**许可风险被隔离且可逆**。

## 5. 后端许可 × 兼容目标权衡

| 路线 | 后端 | 许可 | 字节级兼容 | Windows MSVC |
|---|---|---|---|---|
| A | rug（动态 LGPL） | 自身 Apache + LGPL 动态链接 | **易**（同一 MPFR） | 需 GNU 工具链（摩擦） |
| B | dashu + feanor（全 MIT） | **全宽松** | 难（数字生成需适配） | **友好** |
| C | malachite + feanor | 自身 Apache + LGPL | 中 | 友好 |

- 用户要"风险最小许可"→ 倾向 **B（全宽松）**；但要"字节级 + 成熟可靠"→ 倾向 **A（rug）**。
- **工程解**：facade 使两者可切换；**M0 原型定夺默认**（ADR-8）。建议：以 **A 为字节级参考路径**（动态 LGPL 合规、成熟），同时保留 **B 作为全宽松可选后端**；若用户把许可纯净置于字节级便利之上，则默认 B 并投入数字保真适配。

## 6. 合规清单

- [ ] 仓库根 `LICENSE`（Apache-2.0 全文）+ `NOTICE`（归属/第三方声明）。
- [ ] 若双许可：`LICENSE-MIT` + `LICENSE-APACHE`，README 说明任选。
- [ ] 依赖许可证登记（cargo-deny / 清单），CI 校验许可合规。
- [ ] LGPL 后端**动态链接**；若静态分发，提供可重链接目标文件/源码（LGPL 义务）。
- [ ] 净室溯源记录（docs/provenance/）。
- [ ] 不复制 Sollya/Gappa 代码；生成 .g 文件仅为数据输出。
- [ ] 法务审查净室主张与依赖合规。

**小结**：自身代码 **Apache-2.0**（风险最小宽松协议）+ **净室方法 + 溯源 + 法务审查** + **依赖优先宽松、LGPL 动态链接、facade 隔离可逆**。这套组合在"不复制 Sollya 代码"前提下，把法律风险降到可接受水平，同时保留字节级兼容与成熟后端的工程选项。
