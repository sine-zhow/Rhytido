# 净室溯源记录（Clean-Room Provenance）

> 目的：为"Rhytido 是 Sollya 的**独立净室实现**、非衍生作品"这一许可证立场留存**可核查证据**。
> 本目录是治理文档，非实现代码。每个实现模块在落地时填写一份溯源记录（用 [TEMPLATE.md](TEMPLATE.md)）。
> **如实声明**：溯源记录是降低风险的手段，**不构成法律保证**；最终须法务审查（见 `docs/plan/04-license-and-cleanroom.md`）。

## 为什么需要

Sollya 为 CeCILL-C（文件级弱 copyleft）。只有**复制了其代码/表达**的文件才受其约束；独立实现可自选 Apache-2.0。因此"是否独立实现"是许可证安全的关键，需要证据支撑。

## 必须正视的风险（R1）

本项目在规划期**深度精读过 Sollya 源码**。严格净室理想上要求"规格编写者"与"实现者"分离（实现者只看规格、不看源码）；我们两者同一，净室主张的可辩护性被削弱。**缓解**（也是本记录要证明的）：
- 实现以**公开规格**为准：Sollya 公开文档、数学论文、**行为测试**（输入→输出契约），而非对照源码逐行翻译。
- 采用**独立的 Rust 设计**（interning/facade/分层/所有权），与 Sollya 的 C 表达天然不同。
- 逐模块留存**规格来源 + 独立设计理由 + 不复制声明**。
- 法务审查确认。

## 记录什么（每模块一份）

1. **规格来源**：本模块依据的公开文档章节 / 论文 / 行为测试（附链接或语料编号）。算法/数学方法本身不受版权保护，规格来源证明实现依据的是思想而非表达。
2. **独立设计说明**：Rust 侧的接口/数据结构的**自主设计理由**，及其与任何参考表达的差异。
3. **不复制声明**：明确未复制 Sollya 源码/注释/命名表达；如有不可避免的通用算法惯例，说明其属公有领域。
4. **行为验证**：用哪些测试/语料验证了行为等价（而非对照源码）。
5. **复核**：同伴复核 + 法务审查状态。

## 何时记录

- 结构与模板：**现在**建立（本目录）。
- 逐模块记录：在对应里程碑（M0+）实现该模块时填写，随 PR 提交、随评审复核。
- 完成判据：每个实现模块都有一份经复核的溯源记录；无记录的模块视为未满足净室门禁。
